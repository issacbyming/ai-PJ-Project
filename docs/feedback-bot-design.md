# LINE 即時回饋機器人設計 — 以新元昌（觀光工廠）為例

> 目標：用 LINE Bot 在 5–7 分鐘內收完 2–3 題關鍵調研、能依回答追問、最後發優惠。
> 核心難題：遊覽車團客「下車 → 體驗 → 逛逛 → 結帳 → 上車」的流程裡，找不到填答的切入點；體驗或結帳結束後再請他填，動機很弱，因為他大概不會再來。

---

## 1. 先回答最苦惱的問題：收集時機

### 1.1 把「填完才給」倒過來：先給，再問

傳統做法是「填問卷 → 拿折價券」。對一個不會再來的人，折價券的價值趨近於零，所以沒人填。

倒過來做：

1. 顧客一下車（或體驗開始前），掃 QR 加 LINE 好友，**立刻拿到一張「今天結帳現折」的優惠券**（例如折 50 元或試喝升級）。這一步不問任何問題，只有給。
2. 優惠券綁 LINE 使用者 ID，結帳時櫃台掃券或輸入短碼核銷。
3. 核銷成功的那一刻，Bot 知道「這個人剛買完」，立刻用一句話開場：「謝謝你今天帶走了茶 🍵 幫我記住兩件事，之後喝完想回購會比較方便」，接著才問題目。

為什麼有效：

- 互惠原則：先收到好處，再被請求小事，答應率遠高於「做事換好處」。
- 優惠在**離開前**就被用掉，不依賴「下次來」。
- 核銷動作本身就是 Q2（購買行為）最可靠的資料來源，不必靠使用者回想。
- 加好友發生在流程最前面，Bot 之後有完整的窗口可以分段推訊息。

### 1.2 把一份問卷拆進旅程裡的「等待時間」

團客流程看起來沒有空檔，其實有三段被動等待：

| 旅程階段 | 典型等待 | 可以做的事 | 耗時 |
|---|---|---|---|
| 下車集合、進場前 | 等整團到齊、聽解說開場 | 掃碼加好友 → 領現折券（不問問題） | 30 秒 |
| 體驗結束（例：揉茶 DIY 做完、品茶完） | 等成品包裝、等下一站集合 | **Q1 印象最深刻**（1 題 + 1 追問） | 60–90 秒 |
| 結帳完 / 走回車上 / 車剛開 | 排隊、等人上車、車上前 10 分鐘 | **Q2 購買原因 + Q3 樣貌**（2 題 + 追問） | 2–3 分鐘 |

每一段都只有 1–2 題，單次互動不超過 90 秒，加總落在 4–5 分鐘，低於 5–7 分鐘的上限，也不會讓人覺得「在填問卷」。

觸發方式：

- 體驗桌上的 QR 或導覽員口頭一句「掃這個，等一下結帳現折」。
- 結帳核銷事件（最可靠）。
- 若沒有核銷事件，用「加好友後 N 分鐘」或「團體代碼的預定離場時間」做保底推送。

### 1.3 離場後的優惠，要換成「用得到」的形式

茶、糕餅這類觀光工廠商品的共同特性是**回購型 + 送禮型**。離場後的優惠不要再給「下次到店折價」，改成：

- **線上回購券 + 免運**：茶喝完了直接在 LINE 下單。這同時是 CRM 的起點，不是一次性的問卷獎勵。
- **轉贈券**：「送一張給你想送茶的人」。送禮型顧客會自己把券轉出去，等於幫你獲客。
- **回購提醒**：依購買量估一個「差不多喝完」的時間點，30–45 天後推一句問候 + 券。

這一步也呼應 Q2：回答「自用」的人收回購券，回答「送禮」的人收轉贈券，資料直接變成行動。

### 1.4 善用團體結構：導遊 / 領隊

團客有一個散客沒有的槓桿：整團被同一個人帶著。

- 入場時導遊拿到「團體代碼」，顧客加好友時輸入或掃團體 QR，所有回答自動帶旅行社、團型、人數標籤。
- 整團填答率達門檻（例如 60%）→ 導遊拿回饋（下次帶團的伴手禮或抽成），讓導遊在車上幫你催一句。
- 車上前 10 分鐘是全場最安靜、最沒事做的時間，Bot 推送的開啟率會最高。

## 2. 「有智慧的引導」怎麼做，又不失控

### 2.1 結構：固定骨架 + LLM 填血肉

不要讓 LLM 完全自由發揮，也不要寫死一問一答。做法是：

- **骨架（程式控制）**：三個「錨點題」固定順序、固定的進度與時間預算、每題最多 1 次追問、使用者可隨時跳過、沉默就存檔結束。
- **血肉（LLM 控制）**：看了使用者的回答之後決定要不要追問、追什麼、怎麼承接語氣；並把自由文字抽成結構化欄位和標籤。

每一輪 LLM 的輸入是「問卷腳本 + 目前狀態 + 使用者這句話」，輸出固定格式：

```json
{
  "reply": "你說揉茶最有印象，是因為有動手做，還是因為老師講的那段故事？",
  "next_action": "probe",          // probe | advance | end
  "extracted": {
    "q1_highlight": "揉茶 DIY",
    "q1_reason": null
  },
  "tags": ["體驗導向"]
}
```

程式只信 `next_action` 和 `extracted`，並且強制執行預算：

- 單題追問次數 ≤ 1（可設 Q2 允許 2 次，因為它價值最高）。
- Bot 總回合數 ≤ 10。
- 每則訊息 ≤ 2 行，不講道理不解釋。
- 使用者說「不想回答 / 跳過 / 沒有」→ 直接 advance，不再追。
- 使用者 3 分鐘沒回 → 存目前進度，不補發催促（下一個等待時間點再接續）。

這樣「智慧」體現在三處：**判斷答案夠不夠具體、追問的措辭、把口語抽成標籤**，而進度與時間始終在程式手上。

### 2.2 追問規則（LLM 的判斷依據）

| 使用者回答狀態 | 動作 | 範例 |
|---|---|---|
| 具體（有名詞 + 有原因） | 承接一句，advance | 「揉茶的時候手會黏黏的很好玩」→「哈哈那個手感確實難忘，下一題…」 |
| 模糊（只有名詞） | probe 一次 | 「DIY」→「DIY 裡最有感的是哪一刻？動手的時候，還是最後拿到成品？」 |
| 負面 | 先接住，再問「哪裡可以更好」 | 「有點趕」→「謝謝你直說。如果多 10 分鐘，你最想多留在哪一段？」 |
| 跳過 / 沉默 | advance 或 end | — |
| 離題或閒聊 | 一句回應，拉回錨點 | — |

### 2.3 用 LINE 的介面特性降低輸入成本

- **Quick Reply 按鈕**：錨點題用按鈕給 4–6 個選項 + 「其他」，一按就答。
- **自由文字 / 語音訊息**：只在追問時開放。長輩團很多，語音訊息轉文字（STT）會顯著提高完成率。
- **Flex Message**：優惠券、進度條（「還有 1 題」）、購買摘要卡。
- **LIFF 小頁面**：給櫃台用的核銷頁（輸入 4 碼短碼），不必整合 POS 也能運作。
- **Rich Menu**：填完之後變成「我的茶 / 沖泡方式 / 回購」，Bot 從問卷工具變成顧客入口。

## 3. 題目設計（三個錨點 + 追問方向 + 要抽出的欄位）

### Q1 體驗印象（體驗結束後推送）

- 錨點：「今天哪一段最讓你有印象？」Quick Reply：導覽解說 / 揉茶 DIY / 品茶 / 賣場逛逛 / 環境空間 / 其他
- 追問（擇一）：「是哪一刻？」或「為什麼是這段？」
- 可選負向：「有哪一段覺得可以再更好？」（只問一次，不追）
- 抽出：`highlight_stage`, `highlight_reason`, `improvement_stage`, `sentiment`
- 給營運的用法：各站「印象分」排行、投資哪一站、哪一站要修。

### Q2 購買（核銷後或結帳後推送，價值最高）

- 錨點 A：「今天帶走了什麼？」若有核銷資料直接帶出品項確認；沒有則 Quick Reply 分類。
- 錨點 B：「自己喝，還是送人？」自用 / 送禮 / 兩者
- 追問：「是什麼讓你決定買的？」Quick Reply：試喝好喝 / 導覽介紹到 / 有優惠 / 包裝好看 / 同團有人買 / 其他
- **沒買的人同樣重要**：「今天沒有帶東西走，是價格、沒有想要的品項，還是行李不方便？」
- 抽出：`purchased_items`, `purchase_purpose`, `purchase_trigger`, `non_purchase_reason`, `basket_size`
- 給營運的用法：試喝的轉換貢獻、導覽話術對銷售的影響、送禮比例決定包裝策略、沒買原因決定是否推宅配。

### Q3 顧客樣貌（最多 1 題主動問，其餘被動取得）

- 被動：LINE 顯示名稱 / 頭像、團體代碼（旅行社、團型、出發地）、到訪時段、是否核銷、購買金額。
- 主動（擇一，Quick Reply）：「今天跟誰一起來？」家人 / 朋友 / 公司同事 / 一個人；或「平常喝茶的習慣？」每天 / 偶爾 / 幾乎不喝
- LLM 推導標籤：`送禮者`、`自用回購潛力高`、`價格敏感`、`體驗導向`、`故事導向`、`銀髮團`、`親子團`
- 給營運的用法：之後的回購推播分群、旅行社談合作的依據、商品開發方向。

### 時間預算

| 階段 | 題數 | Bot 回合 | 預估 |
|---|---|---|---|
| 入場領券 | 0 | 2 | 30 秒 |
| Q1 | 1 + 1 追問 | 3 | 60–90 秒 |
| Q2 + Q3 | 3 + 1 追問 | 5 | 2–3 分鐘 |
| 結尾發券 | 0 | 1 | 15 秒 |
| **合計** | | **≤ 11** | **約 4–5 分鐘** |

## 4. 提高填答率的做法（整理）

1. **先給再問**：加好友就拿券，問題在券被用掉之後才出現。
2. **優惠在離開前就能用**：結帳現折，不賭「下次」。
3. **問在等待時間**：體驗後、結帳後、車上，而不是在他趕路的時候。
4. **拆短**：每次 1–2 題、90 秒內，顯示進度。
5. **按鈕優先，語音補位**：打字是最大的流失點。
6. **把問卷包裝成服務**：「幫你記住今天買的茶、沖泡方式、回購連結」，使用者是在整理自己的東西，不是在幫你填表。
7. **團體槓桿**：導遊有回饋、整團有進度，車上互相提醒。
8. **離場後的獎勵改成回購券、免運、轉贈券**，而且依 Q2 的答案分流。
9. **現場人員一句話**：櫃台結帳時「掃這個現折 50」比任何海報有效。
10. **容許不完整**：答一題也存一題，不要為了完成率把人卡在流程裡。

## 5. 技術架構（MVP）

```
顧客 LINE ──► LINE Messaging API webhook
                     │
                     ▼
            Bot 伺服器（Node/TS）
            ├─ 對話狀態機（錨點、預算、進度）
            ├─ LLM 對話層（Claude，結構化輸出：reply / next_action / extracted / tags）
            ├─ 優惠券服務（發券、短碼、核銷）
            └─ 排程推送（體驗後、離場後、回購提醒）
                     │
                     ▼
            Postgres（Supabase）
            visitors / groups / sessions / answers / tags / coupons / redemptions
                     │
                     ▼
            櫃台 LIFF 核銷頁  ·  營運儀表板（各站印象分、購買觸發、標籤分佈）
```

資料表重點：

- `visitors`：line_user_id、display_name、group_id、first_seen_at
- `groups`：團體代碼、旅行社、團型、預定離場時間、導遊 ID
- `sessions`：visitor_id、stage（intake/q1/q2/q3/done）、turn_count、started_at、last_message_at
- `answers`：session_id、question_key、raw_text、extracted(jsonb)
- `tags`：visitor_id、tag、source（llm/rule）、confidence
- `coupons` / `redemptions`：code、type（現折/回購/轉贈）、issued_at、redeemed_at、redeemed_by_staff、amount

對話腳本（錨點題、選項、追問策略、抽取欄位）放成一份 JSON，換場域（另一間觀光工廠）只改腳本不改程式。

## 6. 新元昌試行計畫（兩週）

- 第 1 週：入場領券 + Q2（核銷後）。只做兩個觸點，先驗證「先給再問」的加好友率與完成率。
- 第 2 週：加入 Q1（體驗後）與 Q3、導遊團體代碼、離場後回購券。
- 要看的指標：

| 指標 | 目標（試行） |
|---|---|
| 到訪者加好友率 | ≥ 40% |
| 現折券核銷率 | ≥ 60% |
| 核銷後 Q2 完成率 | ≥ 50% |
| 全部三題完成率 | ≥ 30% |
| 每人平均互動時間 | ≤ 5 分鐘 |
| 標籤覆蓋率（至少 1 個行為標籤） | ≥ 70% |
| 離場後 30 天回購券使用率 | 先量測，不設目標 |

- 風險與對策：
  - 導遊趕行程 → 把開場縮到 30 秒，券的訴求放在「結帳現折」而不是「填問卷」。
  - 現場訊號差 → QR 導向的是 LINE 加好友，不是網頁；Bot 訊息很輕。
  - 個資 → 加好友的第一則訊息放告知事項與用途說明；標籤只做分群不做個別揭露。
  - 櫃台負擔 → 核銷只需輸入 4 碼，或直接掃 Flex 卡上的條碼。
